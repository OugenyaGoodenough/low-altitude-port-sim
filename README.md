# 低空港 —— 无人机分级运行管理与责任追溯系统（仿真演示模块）

中国国际大学生创新大赛参赛项目的技术验证载体：浏览器端 **3D 动态仿真 + 离散事件仿真引擎**，
用于对比"**分级管理**"与"**混合管理**"两种无人机机场运行模式的效率与安全指标，并自动录制演示视频。

- 仿真逻辑全部在引擎中真实运行，页面只负责可视化，**所有指标均可从事件日志复算**；
- 无后端、无外部数据，构建产物可直接静态托管；
- 固定随机种子，**结果完全可复现**。

## 一、快速开始

```bash
npm ci                 # 安装依赖（Node >= 20）
npm run dev            # 开发预览 → http://localhost:5173
npm run build          # 构建静态产物到 dist/
npm run preview        # 预览构建产物 → http://localhost:4173
npm run experiment     # 跑对照实验，输出 public/results/{experiment.json,csv,incidents.json}
npm run record         # 录制演示视频 → public/demo/low-altitude-port-demo.mp4
node scripts/shot.mjs  # 截图 + 性能 + 确定性自检 → public/shots/
node scripts/probe_terrain.mjs  # 地形遮挡核验（射线步进）
```

页面 URL 参数：

| 参数 | 取值 | 说明 |
|---|---|---|
| `policy` | `graded` / `pooledConservative` / `pooledNaive` | 管理策略，默认 `graded` |
| `load` | `0.6 ~ 2.0` | 负荷水平（机队规模倍数），默认 `1.2` |
| `seed` | 整数 | 随机种子，默认 `20260930` |
| `record` | `1` | 录屏模式：关闭页面自带时钟，仅响应 `window.__sim.renderAt(t)` |
| `ui` | `0` | 隐藏全部 UI 面板（用于干净画面截帧） |
| `t` | 秒 | 初始仿真时刻 |

## 四、仿真模型

### 4.1 仿真类型

离散事件仿真（DES），事件队列 + 闭环机队。每架无人机循环执行：

```
停机坪周转(30/120/90 s) → 申请放行 → 等待放行许可 → 起降通道穿越 → 去程航线
→ 折返点申请进近许可 → 回程航线 → 等待进近许可（空中盘旋） → 通道降落 → 着陆
```

等待放行与空中盘旋的时间即为**延误**，全部由资源竞争产生，不做任何伪造。

### 4.2 机型参数（`src/sim/config.js`）

| 机型 | 最小安全间隔 | 通道内速度 | 起降占用 | 航线时间 | 周转时间 |
|---|---|---|---|---|---|
| 微型四旋翼 | 5 m | 15 m/s | 8 s | 90 s | 30 s |
| 重型多旋翼 | 20 m | 10 m/s | 12 s | 120 s | 120 s |
| 固定翼货运 | 40 m | 35 m/s | 跑道清空 90 s | 420 s | 90 s |

起降通道长度 120 m；通信与反应附加时间 1.5 s。规划负荷机队规模：微型 10 架、重型 3 架、货运 2 架（`load` 参数按此倍数放大，用于负荷扫描）。

### 4.3 物理设施（三种策略下**完全相同**，这是对照实验的公平性基础）

- 停机位 18 个：分级模式为"微坪 12（间距 8 m）+ 重坪 4（间距 24 m）+ 货运坪 2（间距 48 m）"；混合模式为"通用坪 18（间距 10 m）"混排。
- 起降通道 4 条：分级模式为"微坪通道 2 + 重坪通道 1 + 货运跑道 1"（专属）；混合模式为"通用通道 3 + 共用跑道 1"（任意机型可用）。

**三种策略的差异只来自管理规则**：

| 策略 | 场地分配 | 放行间隔规则 |
|---|---|---|
| `graded` 分级 | 专属 | **按机型分级**：微型 4 s、重型 12 s、货运按跑道清空 90 s |
| `pooledConservative` 混合-保守 | 共用 | **统一取最保守机型**：12 s（重型升空间隔） |
| `pooledNaive` 混合-经验 | 共用 | **统一经验值**：4 s（未区分机型速度差异） |

### 4.4 冲突判定（几何判定，确定性）

- **空中间隔侵入**：同一通道、同方向的前后两架，在走廊重叠区间内逐时刻计算间距
  `gap(t) = v_前·(t-t_前) - v_后·(t-t_后)`；若最小值 `< max(两机型最小安全间隔)` 即为冲突。
  由于走廊长 120 m、机型速度差异大（15/10/35 m/s），**统一 4 s 间隔在混合运行下必然出现追尾**；
  而分级通道内同机型速度一致，间隔天然满足。
- **地面停机间隔侵入**：相邻停机位被同时占用且物理间距 `< max(两机型最小安全间隔)`。
  混合模式通用停机位间距 10 m，**不满足重型 20 m / 货运 40 m 的要求** → 只要相邻位同时有人即构成违例（按"违例共存事件 + 持续时长"统计，同一对停机位只记一次）。

### 4.5 责任追溯日志链

引擎记录三类日志，冲突发生时自动回溯：

1. `CMD`（放行指令）：`{id, t, 执行主体=无人机运行服务站（调度）, 机型, 通道, 指令放行时刻, 假设间隔, 假设航速, 规则}`
2. `EXE`（飞手执行）：`{id, ref=CMD, 实际进入时刻, 时刻偏差 dt, 实际航速, 速度偏差 dv, 判定=ADHERE/DEVIATION}`
3. `CFT`（冲突事件）：`{id, 类型, 实测间距, 要求间距, 严重程度, 涉及双方, 关联 CMD/EXE}`

**责任判定规则**：若涉及方的飞手执行偏差超过容差（`|dt| > 5 s` 或 `|dv| > 12%`）→ 判为**飞手违规**；
否则判为**调度指令错误**（空中：统一间隔未区分机型速度差异；地面：停机位分配未按机型间隔分区）。
每条冲突都会生成 `autopsy`，含结论、责任主体与逐条证据（`basis`），可在页面右侧面板点开查看完整链条 `CMD → EXE → CFT`。

飞手偏差按 6%/次动作的概率随机产生（固定种子下可复现），因此**分级模式也会出现少量飞手责任事件** —— 这正是责任追溯要区分的场景。

## 五、对照实验结果（真实跑出，种子 20260930，仿真窗口 2 h，含 15 min 热机）

### 5.1 规划负荷（`load = 1.0`，机队 微型10 / 重型3 / 货运2）

| 策略 | 吞吐量（架次/h） | 平均延误（s） | 冲突次数（空中/地面） | 停机坪利用率 | 调度责任 | 飞手责任 |
|---|---|---|---|---|---|---|
| **S1 分级** | **308.6** | **5.6** | **1**（1 / 0） | 22.6% | 0 | 1 |
| S2 混合-保守 12 s | 292.0 | 13.5 | 118（4 / 114） | 24.5% | 114 | 4 |
| S2 混合-经验 4 s | 312.0 | 2.2 | 114（21 / 93） | 21.8% | 108 | 6 |

### 5.2 高负荷（`load = 2.0`，机队 微型20 / 重型6 / 货运4）

| 策略 | 吞吐量 | 平均延误 | 冲突次数 | 停机坪利用率 |
|---|---|---|---|---|
| **S1 分级** | **556.6** | **26.5 s** | **4** | 52.6% |
| S2 混合-保守 | 475.4（−14.6%） | 52.9 s（2.0×） | 595 | 69.7% |
| S2 混合-经验 | 577.7（+3.8%） | 19.7 s | 961 | 51.3% |

### 5.3 结论（请按此口径引用）

1. **在"必须满足各机型安全间隔"的前提下，混合管理只能采用统一保守间隔**：此时分级模式吞吐量高 5.7%（规划负荷）～17%（高负荷）、平均延误低 58%～50%、且没有调度责任的间隔侵入。
2. **若混合管理为追求效率改用统一经验间隔**：吞吐量与延误可与分级模式持平甚至略优，但**冲突次数上升两个数量级**（114～961 次 vs 1～4 次），且绝大多数责任在调度方（统一间隔未区分机型速度差异）。
3. **地面维度**：混合模式的通用停机位（间距 10 m）无法同时满足重型 20 m / 货运 40 m 的地面间隔要求，运行中出现 93～591 次地面间隔侵入；分级模式的专属场地按机型间隔设计，地面冲突为 0。
4. 因此分级管理的价值不是"单点指标最优"，而是**同时取得效率与安全**：无论混合管理偏向保守还是偏向激进，都会在效率或安全的一侧失分。

> **计划书引用提示**：上述结论对"统一保守间隔 = 12 s"这一假设敏感（该值取重型机型的升空间隔）。
> 若评委追问，可直接修改 `src/sim/config.js` 中 `pooledConservative.uniformHeadway_s` 并重跑 `npm run experiment`，
> 一分钟内即可得到新的对照表——这也是本项目"参数可追溯、结论可复算"的设计目的。

## 六、仿真假设与参数（答辩/计划书必须说明的部分）

1. **瓶颈资源**：在本参数集下停机坪利用率仅 22%～70%，**瓶颈是起降通道而非停机坪**；因此分级管理的收益主要来自"通道专属化 + 间隔规则精细化"。若要考察停机坪瓶颈，把 `FLEET_BASE` 放大或把周转时间调长即可。
2. **统一间隔是"粗放管理"的建模假设**：混合模式取 12 s（保守）或 4 s（经验），代表"管理颗粒度粗、按最大公约数放行"的现实做法；这是本项目要解决的问题本身，而不是为得到结论而设的陷阱——两种取值分别演示了"牺牲效率"与"牺牲安全"两条失败路径。
3. **冲突为确定性几何判定**，仅考虑通道内速度差导致的间隔侵入与停机位间距不足；**未建模**气动尾流、风场扰动、通信延迟、导航误差。
4. **未包含 S3 高原气象扰动场景**（规格书标注为"可选进阶"，经确认不做）。
5. 机型几何尺寸为可视化可读性做了放大（微型约 9.6 m 轴距等），属概念化演示尺度，不影响任何指标计算。
6. 飞手偏差概率 6%/动作、偏差容差（5 s / 12%）为演示用设定值，可在 `src/sim/engine.js` 的 `_rollDeviation` 与 `_autopsy` 中调整。
7. 指标窗口：仿真总时长 7200 s，前 900 s 为热机（不计入指标），统计窗口 6300 s。
8. 演示视频为**无声**画面，用于计划书插图与答辩投影。

## 七、演示视频

- 文件：`public/demo/low-altitude-port-demo.mp4`（1920×1080 / 30 fps / H.264 / 约 110 s）
- 录制方式：Playwright 驱动 Edge（headless + 硬件加速 ANGLE/D3D11）逐帧调用 `window.__sim.renderAtNextFrame(t)`，
  截图经**管道**直接交给 FFmpeg 编码（帧不落盘），因此录制过程可重复、画面与仿真时刻严格对应。
- 分镜：开场全景 → 分级模式三类无人机并行运行 → 运行服务站视角 → 混合模式冲突告警 → 责任追溯日志链回放 → 混合-保守效率代价 → 两模式指标对比 → 结尾。
- 视频中的告警分镜会自动定位到引擎实际产生的冲突事件（`meta.conflictList`），指标字幕取自 `public/results/experiment.json`，**与仿真数据一致**。

重新录制：`npm run record`（可用 `OUT=...` 指定输出、`LOAD=...` 指定负荷、`--dry 60` 快速试录）。
